## 1. 核心危机：当前最危险的双轨割裂现状

在当前代码库中，系统存在两套完全并行的交易与执行链路。**回测链路**已升级为全新的持仓量共振策略与币安 VIP0 成本模型，但**纸面模拟与实盘工作链路**依然运行在历史遗留的旧 v3.1 执行核心、旧 3a/3b/3c/3d 四臂逻辑上，且内部深埋外部绝对路径与 Worktree 幽灵依赖。

### 1.2 双轨现状的致命缺陷

1. **策略脱节**：前端与回测测出的是 `WX_OI_RESONANCE_V1`（持仓量共振），而 `paper_engine.py` 与 `live_worker.py` 内部跑的依然是旧的 `3a/3b/3c/3d` 四臂逻辑，导致“回测的策略无法上线，纸面模拟的策略不是回测策略”；
2. **成本模型分叉**：回测已严格执行币安普通用户（VIP0）万2/万5与数据库历史实际结算周期（`settlement_events`）；纸面引擎内部却沿用固定万5费率与宽松的兜底假设；
3. **幽灵依赖地雷**：`paper_engine.py` 内部硬编码引用了已不存在的外部机器路径 `/Users/boos/WorkBuddy AI/...` 与 `/.codex/worktrees/c9d7/...`，由于具备 `FALLBACK` 容错逻辑，这些错误被掩盖，导致系统在失活状态下静默运行伪参数；
4. **两套账本各自为政**：回测生成轻量闭合的 `ledger.csv` 与 `summary.json`；纸面模拟自建 SQLite 数据库 `paper_{arm}.sqlite3`，字段体系与核算规则不互通，导致关卡 2（Paper ≈ Backtest）在物理上根本无法对齐。

## 2. 收敛目标：Shared Trading Core 统一架构

彻底废弃双轨，将策略、信号、风控、订单、执行、持仓、成交、账本彻底收敛为**唯一共享交易核心（Shared Trading Core）**。回测（Backtest）、纸面模拟（Paper）与实盘接入（Live）仅作为**数据泵（Data Feed Adapter）**与**订单路由（Order Route Adapter）**的驱动插件，底层核心代码 100% 共享。
