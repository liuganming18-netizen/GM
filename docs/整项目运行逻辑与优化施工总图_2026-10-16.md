## 0. 一句话总纲

> 这个项目**已经有一套能跑通的回测内核**（新策略 `WX_OI_RESONANCE_V1` + 币安 VIP0 成本模型 + 31 项账本恒等式），
> 但**纸面模拟（Paper）和实盘（Live）还挂在旧的 3a/3b/3c/3d 四臂链路上**，并且中间夹着两条断线：
> ① 冻结研究件丢失（Live 一导入就崩）；② 纸面账本目录不存在（Paper 拒绝启动）。
>
> 所以现在**唯一要做的事**：把"回测那套已经验证过的内核"抽成**一个共享交易核心**，
> 让 Backtest / Paper / Live **共用同一份**策略、风控、撮合、账本代码，
> 而不是各写一套。收完这道口子，项目才算真正闭环。

## 5. Data → Strategy → Signal → Risk → Order → Execution → Position → Trade → Ledger 完整数据流

### 5.1 逐段说明

```
【Data】market_v2.sqlite3（热）+ Parquet（冷）
   │  · 1h 信号周期 + 15m 执行周期
   │  · OI/资金费/多空比按事件可用时戳(PIT)对齐，严禁未发布数据
   │  · 缺口/重复 bar 强制阻断
   ▼
【Strategy】WX_OI_RESONANCE_V1.evaluate()
   │  · 仅用已收盘确认 K 线
   │  · 输出：标的 / 方向 / 强度 / 止损位 / 可用时戳
   │  · 未来函数截断核验：截断至 t 的信号 == 全样本 t 时刻信号
   ▼
【Signal】规范化信号事件
   │  · 字段：symbol / side / strength / available_at / oi_resonance
   │  · 时间网格连续性校验（缺 bar 即拒绝，不静默补）
   ▼
【Risk】trading_core/risk.py 纯函数校验
   │  · 单笔风险 ≤ 0.8% 权益
   │  · 最大并发 ≤ 3
   │  · 杠杆 ≤ 2.0x，保证金 ≤ 40%
   │  · 超限 ⇒ 直接拒绝入场（不是警告）
   ▼
【Order】trading_core/order.py 状态机
   │  · PENDING → FILLED / REJECTED / CANCELED
   │  · 字段：order_id / client_oid / symbol / side / qty / limit_px / state
   ▼
【Execution】trading_core/execution.py 统一撮合
   │  · 信号 bar 收盘触发 → 下一根 bar 开盘成交（Conservative Next-Open）
   │  · 同 bar 同时触止损止盈 ⇒ 按先止损结算
   │  · 滑点：跳空最劣；手续费：Maker 万2 / Taker 万5
   ▼
【Position】trading_core/position.py 持仓跟踪
   │  · 阶梯杠杆上限 / 维持保证金 / 强平价
   │  · 未实现盈亏按标记价计算
   │  · 支持快照导出导入（重启幂等）
   ▼
【Trade】trading_core/trade.py 标准化成交
   │  · 严格区分 maker/taker
   │  · 记录滑点点位 + 损耗 U 额
   ▼
【Ledger】trading_core/ledger.py 统一账本
   · 31 项算术恒等式：
     初始资金 + 累计已实现盈亏 − 累计手续费 − 累计资金费 − 累计滑点损耗 == 最终权益
   · 资金费按实际结算周期事件计提（非固定假设）
   · 重启后自愈校验：无孤儿持仓、无悬挂订单、不重复扣费
```

### 5.2 当前 vs 优化后差异速查

| 环节 | 当前 | 优化后 |
|---|---|---|
| Data | 热冷双层健康，但含幽灵路径 | 统一网关，零绝对路径 |

| Execution | 三套滑点/费率算法 | 统一撮合 |
| Position | 分散维护 | 统一跟踪器 |
| Trade | 字段不互通 | 标准化成交 |
| Ledger | CSV vs SQLite 脱节 | 统一双式记账本 |

## 7. AI 应该放在哪里、不能碰哪里

> 这一节划的是**红线**。项目里 AI（含本助手、Codex、Gemini 等）参与施工，但必须清楚边界。

### 7.1 AI 应该放在哪里（可以做的）

| 位置 | 职责 | 理由 |
|---|---|---|
| **代码审查与静态扫描** | 扫描幽灵依赖、重复实现、旧桥调用 | 机械、可验证、无副作用 |
| **文档与蓝图编制** | 生成施工图、验收标准、迁移清单 | 纯输出，不影响运行 |
| **测试与证据生成** | 跑单测、生成验收 JSON、逐笔对账 | 只读 + 产出证据文件 |
| **重构执行** | 按蓝图拔除硬编码、抽象共享核心 | 有明确验收关卡兜底 |
| **独立复核** | 换一个 AI 交叉核对另一个 AI 的产出 | 避免自证清白 |
| **参数/数据核对** | 逐事件核对 OI 原件、缺口原件 | 只读比对 |

### 7.2 AI 不能碰哪里（红线）

| 禁区 | 原因 |
|---|---|
| ❌ **不得凭空重建丢失的账本/参数视图** | 原账本已不可恢复，伪造数据会污染历史基线 |
| ❌ **不得自动生产切流 / 重启健康服务** | 服务切换由「账本保全」窗口独占；其他窗口不得自行重启 8787 |
| ❌ **不得在数据层塞历史数据** | 热层是近 34 天滚动窗，塞历史将来下沉会重复 |
| ❌ **不得用 `0` 或空库冒充缺失结果** | 缺结果必须 `null` / fail-closed |
| ❌ **不得删除原件 / 解除不可变锁 / 覆盖目标冲突** | 只增不删，原件永久保留 |
| ❌ **不得在无用户明确授权下启动实盘** | 实盘需单独授权 + 熔断线 |
| ❌ **不得修改业务代码的同时声称"未改动"** | 任何改动必须留 diff + SHA |
| ❌ **不得并行运行两个重建/迁移进程** | 共享旧恢复目录保持唯一写锁 |

### 7.3 一句话原则

> **AI 可以做"读、算、写文档、写测试、按蓝图改代码"；
> 不可以做"造数据、切生产、删原件、绕过门禁"。**
