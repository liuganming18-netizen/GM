## 2. 订正两条归因

### 2.1 SOON：是**入场**越界，出场干净

直接从 `orders.jsonl` 与 `fills.jsonl` 实证（`表1_两腿订正.csv` 第 3、4 行）：

| 腿 | `action` | `side` | `reason` | `order_type` | `fills` 交叉 | 成交时间 |
|---|---|---|---|---|---|---|
| **入场** | `open` | `BUY` | `entry` | `MARKET` | `fill_price=0.16, action=open` ✓ | 2025-07-31T08:15:00Z |
| **出场** | `exit_max_holding` | `SELL` | `max_holding_expired` | `STOP_MARKET` | `fill_price=0.5, action=exit_max_holding` ✓ | 2025-08-10T08:15:00Z |

逐段复算：

| 项 | 入场 | 出场 |
|---|---|---|
| 参考价 | `bar.open = 0.15557` | `bar.open = 0.50549` |
| 滑点后（3bps） | `0.155616671`（+0.000046671） | `0.505338353`（−0.000151647） |
| 取整后（step 0.01） | **`0.16`**（ceil） | **`0.5`**（floor） |
| 记录成交价 | `0.16` ✓ 逐位一致 | `0.5` ✓ 逐位一致 |
| K 线 O/H/L/C | 0.15557 / **0.15557** / 0.15358 / 0.15448 | 0.50549 / 0.51097 / **0.4903** / 0.50227 |
| 越界 | **0.00443（2.847593%）above_high** | **0**（0.5 ∈ [0.4903, 0.51097]） |
| 拆解 | 滑点段 0.0000467（1.05%）+ 取整段 0.004383（98.95%） | — |
| 容差 `raw×slip` | 0.0000466710 | 0.0001516470 |
| 越界 > 容差 | **是** | 否（无越界） |

**订正 P06 第 229 行**：那句「SOON 出场（2.8%，滑点 1.1%）」有两处错 ——
① **腿别错**：2.8% 属于**入场**，出场在区间内；
② **占比错**：入场的滑点段只占 **1.05%**，不是 1.1%（数值接近，但归属不同一条腿，不能互相顶替）。

注意这条 K 线的 `H == O == 0.15557`（光头阳线），所以 3bps 的买入滑点**必然**把价格顶出 high 一点点 —— 这是「该 bar 容不下这个滑点」的典型，不是「滑点导致越界所以不该拒」。

### 2.2 XMR：滑点段已越界，取整再叠加

| 项 | 入场 | 出场 |
|---|---|---|
| 实证 | `open/BUY/entry/MARKET` | `exit_max_holding/SELL/max_holding_expired/STOP_MARKET` |
| 参考价 | `bar.open = 132.88` | `bar.open = 133.98` |
| 滑点后 | `132.919864`（+0.039864） | **`133.939806`**（−0.040194） |
| 取整后 | `132.92` ✓ | **`133.93`** ✓ |
| K 线 | O 132.88 / H 132.97 / L 132.21 / C 132.25 | O **133.98** / H 134.36 / L **133.98** / C 134.2 |
| 越界 | 0（在区间内） | **0.05（0.037319%）below_low** |
| 拆解 | — | **滑点段 0.040194（80.39%）+ 取整段 0.009806（19.61%）** |
| 容差 | 0.0398640 | **0.0401940** |
| 越界 > 容差 | 否 | **是**（0.05 > 0.040194） |

这条 K 线 `L == O == 133.98`（光头阴线），卖出滑点必然把价格压到 low 之下。所以：

- **滑点段那 0.040194 是「模型与数据的边界冲突」**：该 bar 的最低价就是开盘价，3bps 的卖出滑点无处可去；
- **取整段那 0.009806 是取整误差**；
- 两者同向叠加，总越界 0.05，**刚刚好越过容差 0.040194**（超出 0.0098，正好是取整那一段）。

> 顺带说明 C 类的问题：零价腿（SPACE 出场 `fill=0.0`、TAG 出场 `fill=0.0`）的越界量必然远大于容差，所以它们**同时**满足 A 类判据。P06 把 A/B/C 并列成三行，读起来像互斥，实际不是 —— 这也是「25 条」少数一条的原因之一（SOON 出场被塞进 B 类，挤掉了真正的第 26 条）。

### 2.4 所以「闸门必须带容差」这个推论不成立

P06 第 232 行的推理是：「滑点那 0.04 是模型故意保守 ⇒ 闸门必须带容差，否则会把正常成交一起打掉」。

前半句成立（滑点确实是刻意保守），**后半句不成立**：

- 「正常成交」= 35 条区间内的腿，它们的 `over == 0`，**零容差也一条都不会打掉**（实测误伤 0）；
- 容差真正的作用对象是「越界但 ≤ 容差」的腿 —— 实测这个集合**为空**（27 条越界全部 > 容差）；
- 所以容差在 62 腿样本上**没有放过任何一条腿**，却制造了一个「不该拒」的虚构类别。

**结论：删掉容差这个概念，比保留它更安全。** 不是「收紧」，是把一个从未起作用的宽松项去掉。

## 3. 统一 R7 规则与预期

### 3.1 定稿定义（无特例）

```
R7：成交价必须落在该成交 K 线的 [low, high] 闭区间内。

  over = 0                     → 允许
  over > 0                     → 拒绝，reason = fill_outside_bar_range
                                 detail = {fill_price, low, high, over,
                                           raw_price, post_slip_price, price_step,
                                           slip_over, round_over}

参考价格：入场 = bar.open；出场 intrabar_stop = order.stop_price；其余出场 = bar.open
滑点处理：照常计算，但**不构成豁免**；滑点把价格推出区间时，同样拒绝，
          并在 detail 里标记 slip_over > 0（说明「该 bar 容不下这个滑点」）
取整处理：不裁剪、不夹逼。**禁止**把成交价 clamp 到 [low, high] —— 那会把
          「不可能的价格」改成「看着合理的假价格」，等于伪造成交。
边界条件：fill == low 或 fill == high 视为**在区间内**（闭区间）。
```

### 3.2 为什么是零容差，而不是「滑点允许量」

| 论证 | 内容 |
|---|---|
| 物理 | `low`/`high` 是当日**真实成交过**的价格极值。低于 `low` 的卖价、高于 `high` 的买价，在当日市场上不存在。滑点是「成本估计」，不能创造不存在的价格。 |
| 数据 | 62 腿中，「越界但 ≤ 容差」的腿 **0 条** ⇒ 容差从未放过任何一条腿，却制造了「不该拒」的错觉。 |
| 等价性 | 零容差 与 容差=滑点允许量：**拒绝 27 / 误伤 0 / 差异腿 0** —— 在现有样本上两者完全等价。既然等价，取物理上正确的那个。 |
| 反例 | 容差=滑点+1 档：**拒绝 0 条**（27 条全部放行）。因为所有越界量都小于 1 个步长档，这个容差等于把闸门拆了。 |
| 工单约束 | 「不得为保留某笔成交临时放宽规则」⇒ 若为 XMR 单独放宽，就必须解释为什么其它 26 条不放宽。零容差不需要解释任何特例。 |

### 3.3 三种 R7 变体的实测对照（62 腿）

| 变体 | 判据 | 拒绝 | 误伤区间内腿 | 结论 |
|---|---|---|---|---|
| **R7-零容差（定稿）** | `over > 0` | **27** | **0** | 采纳 |
| R7-容差=滑点允许量（P06） | `over > raw×slip` | 27 | 0 | 与定稿等价，但多一个无用概念 |
| R7-容差=滑点+1档 | `over > raw×slip + step` | **0** | 0 | **失效**（27 条全放行） |

差异明细：
- 零容差 vs 滑点容差：**结果不同的腿 0 条**；
- 滑点容差 vs +1 档：**结果不同的腿 27 条**（全部被 +1 档放过），包括 XMR 出场（越界 0.05，+1 档容差 = 0.040194 + 0.01 = 0.050194 > 0.05）。

### 3.5 一句话回答工单的「矛盾」
