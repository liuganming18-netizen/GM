一、本轮新出现的「2 项失败」——已查清，不是本次改动造成的
--------------------------------------------------------------------------------

现象：不设环境变量、按原文件顺序跑 4 个既有回归套件，得到 2 failed / 85 passed。

    FAILED test_backtest_store.py::test_atomic_exclusive_create_and_duplicate_rejected
    FAILED test_backtest_store.py::test_list_runs_reads_docs_and_flags_broken

结论：这是 test_backtest_store.py 自身的「测试隔离缺陷」，由 pytest 文件顺序触发，
      与 WORK-02 零因果关系。

成因（三行代码的相互作用）：
  1) 框架/backend/backtest_store.py:41
     在「模块导入期」读环境变量 OI_RESONANCE_RUNS_DIR 来决定 RUNS_ROOT；
  2) evidence/Work_单策略回测_2026-10-16/test_oi_resonance_v1_backend_p0p1.py:31
     在「模块级」先一步 import backtest_store，此时环境变量还没设，
     于是 RUNS_ROOT 被冻结成项目默认目录；
  3) evidence/Work_单策略回测_2026-10-16/test_backtest_store.py:22-25
     先设环境变量、再 importlib.import_module("backtest_store")，
     但模块已在缓存里，拿回的是同一个旧对象，环境变量的赋值被完全忽略。
  => RUNS_ROOT != TMP，两条断言必然失败。

证据一：同一批 87 个用例，只改顺序或只补环境变量，就 0 失败

    编号  环境变量                              文件顺序              结果
    V1    不设                                  原顺序                2 failed, 85 passed
    V2    不设                                  store 置首            87 passed
    V3    OI_RESONANCE_RUNS_DIR=/tmp/bt_store_test 原顺序             87 passed
    V4    不设                                  仅 p0p1 + store       2 failed, 37 passed

证据二：触发链上的三个文件相对 HEAD 零改动

    框架/backend/backtest_store.py                          git 干净   mtime 10:37:22
    evidence/.../test_oi_resonance_v1_backend_p0p1.py       git 干净   mtime 10:48:26
    evidence/.../test_backtest_store.py                     git 干净   mtime 10:23:05

    HEAD = bd85ccd；git show --stat bd85ccd -- 上述路径 => 输出为空（该提交也没改它们）。
    WORK-02 的改动全部发生在 15:40 之后，且尚未提交。

证据三：WORK-02 改动的模块从不导入 backtest_store

    策略/WyckoffMaster/oi_resonance_v1/execution.py   -> 无
    策略/WyckoffMaster/trading_core/*.py              -> 仅注释/docstring 提到名字，无 import

证据四：最小复现只用「未改动模块」即可成立

    import os, sys, importlib
    sys.path.insert(0, "框架/backend")
    import backtest_store                          # 模拟 p0p1.py:31，此时无 env
    os.environ["OI_RESONANCE_RUNS_DIR"] = "/tmp/bt_store_test"
    m = importlib.import_module("backtest_store")   # 模拟 test_backtest_store.py:25
    # 实测：两次 RUNS_ROOT 完全相同，m is backtest_store == True

附带损害（已封住）：
  V1/V4 每次会往「正式」回测目录 回测日志/oi_resonance_v1/runs/ 写 2 个测试目录，
  界面上会被当成「损坏的运行」列出来。
  处理：原样搬进同级隔离目录（未删除任何文件，可 mv 回退）
        回测日志/oi_resonance_v1/_隔离_误落测试产物_2026-10-16/  共 10 个
  正式 runs 根残留 0；10:22–10:55 的真实运行记录未触碰。

建议修复（本次未实施）：
  在 importlib.import_module 之后补一行  S.RUNS_ROOT = TMP  （或加 assert 显式暴露顺序依赖）。
