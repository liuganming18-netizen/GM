## 1. 缺陷清单（按严重度）

### D1 ★★★ 生产崩溃：`wx_config.load_view()` 必崩（`AttributeError`）

- **位置**：`框架/backend/strategies/wx_config.py`
- **现象**：`wx` 模块（`wx_donchian_wyckoff`）在 commit `46ae755` 被物理删除，该文件留下 `wx = None` 占位，
  但**仍有 5 处** `wx.<常量>` 未清理：
  | 引用 | 行 | 触发路径 |
  |---|---|---|
  | `wx.EFFECTIVE_VIEW_PATH` | `load_view()` | 未显式给 `path`/`WX_EFFECTIVE_VIEW` 时的**默认路径解析** |
  | `wx.EFFECTIVE_VIEW_PATH` | `resolve()` 的 blocked 文案 | 生效配置解析 |
  | `wx.EFFECTIVE_VIEW_PATH` | `approximate_375_registration` 的 view 段 | 375 登记 |
  | `wx.REQUIRED_CONFIG` ×2 | `effective_config()` / `signal_config_for()` | **每次算生效配置** |
  | `wx.ARM_IDS` | 臂校验 | 配置解析 |
- **调用方是真实生产链路**：`wx_execution.py:160`、`wx_gate.binding()`（后者被 `adapter.v1_registered_configs` 使用）。
- **在线实证**（修复前在跑实例，PID 18151）：
  ```
  GET /api/v1/strategies/registered  →  500  {"错误": "读取失败", "类型": "AttributeError"}
  ```
- **修复**：就地重建常量（`ARM_IDS` / `REQUIRED_CONFIG` 18 键，逐字取自被删模块 `8bb8f1b` 的原定义），
  生效视图路径改从**唯一合法来源** `project_paths.EFFECTIVE_VIEW` 解析。
  视图文件本身已丢失 ⇒ `load_view()` 依 `os.path.exists` 如实返回 `(None, None)`，**不伪造、不兜底假值**。
- **修后验证**：`EFFECTIVE_VIEW_PATH` 解析到「若恢复应放哪」的正式路径；`load_view() == (None, None)`；`REQUIRED_CONFIG` 18 个。

### D2 ★★★ 生产崩溃 + 状态码误判 + 内部信息泄露：`adapter._strategy_shape` 硬下标

- **位置**：`框架/backend/adapter.py::_strategy_shape`
- **现象**：注册表条目有**两种形状**：
  - 旧族/退役族（`registry.describe`）含 `required_config` / `config_status` / `timeframe` / `direction`；
  - 「当前回测策略」（`registry.describe_current_backtest`）**不含**这些键。
  旧实现对上述键**硬下标** ⇒ `KeyError: 'required_config'`。
- **连带缺陷**：`KeyError` 是 `LookupError` 子类，被 `Handler.do_GET` 的 `except LookupError → 404` 分支吃掉 ⇒
  **状态码错成 404（"接口不存在"）而非 500**，且把内部键名 `'required_config'` 直接**回显给前端**。
- **在线实证**（修复前）：
  ```
  GET /api/v1/strategy  →  404  {"错误": "'required_config'"}
  ```
- **HEAD 即存在**（已核实 `git show HEAD:…registry.py` 同样不含 `required_config`，`_strategy_shape` 亦非在途改动）⇒ 与并行窗口无关。
- **修复**：改 `.get()` + 显式默认（缺字段一律 `None`/`[]`，符合「缺失一律 None，不用 0 冒充」口径）。
- **修后验证**：对「无 `required_config`」的条目不再抛异常（`params=[]`、`config_status=None`）；
  对「有 `required_config`」的退役族条目**逐字不变**（`decided` 仍随 `frozen`）。

### D3 ★★★ 测试门禁被单行导入打死：`tests/test_business.py` 悬空导入

- **修复**：

  2. 整类删除 4 个**测已删除策略**的类（`ConfigValidationTests` / `StrategyATests` / `StrategyAPrefixTests` / `StrategyBTests`）
     —— 测的是不复存在的功能，只能删（无「迁移」可改指向，commit 已确认生产引用降为 0）；
  3. 保留其中唯一真正测 `common.quantile` 的用例（重命名为 `CommonQuantileTests`，并**先核对实现**确认断言成立）；

### D4 ★★ 测试非隔离：冷层被意外打开，6 个用例被真实数据顶穿

- **根因**：我上一轮（2026-10-17）给 `adapter` 加了「`MARKET_ARCHIVE` **未设置** ⇒ 回落 `project_paths.MARKET_ARCHIVE`」的加固

- **证据特征**：5 个 OI 用例的 `total` 全部等于 `limit`（20000 / 2000），而夹具只有 3456 行。

  行为与迁移前逐字一致。**生产代码不改**（生产侧的回落加固是对的）。

### D5 ★★ 门禁永远非 0：pytest 模块级 skip 在 `unittest discover` 下被记为 ERROR

- **位置**：`tests/{test_history_integrity, test_okx_volume_mapping, test_okx_volume_exec_v3,
  test_okx_volume_fix_isolation, test_okx_volume_fix_rectification, test_pool_gate, test_rest_import_contract}.py`（7 个）
- **现象**：守卫用 `pytest.skip(..., allow_module_level=True)`，抛的是 `_pytest.outcomes.Skipped`，
  **不是** `unittest.SkipTest` 子类 ⇒ `unittest discover` 把它记成 **ERROR** ⇒ `run_tests.sh` 门禁**永远非 0**。
- **实测定性**（本次两轮实验）：
  - 模块级 `raise unittest.SkipTest(...)` → `unittest discover`：`OK (skipped=1)`、退出码 0；
  - 同一写法 → `pytest`：`1 skipped`、退出码 0。
- **修复**：统一改抛模块级 `unittest.SkipTest`（两种 runner 语义一致，仍是「显式 SKIP，非 PASS」），
  并移除已不需要的 `import pytest`（这 7 个文件本是 unittest 模块，不再依赖 pytest）。
- **修后复核**：`unittest` 通道全绿；`pytest` 通道 `2 skipped`（未破坏）。
