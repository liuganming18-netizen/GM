## 二、必须优先处理的 4 个缺口

### ★1 maxQty（最大下单量）完全没有被执行 —— 项2

- **现象**：`InstrumentSpec.max_qty` 会被正确解析（真实快照里六个标的分别是
  2000 / 20000 / 50000 / 70000 / 600000 / 1000000），但引擎的数量闸门只做了
  「向下取整 / ≥ minQty / 名义 ≥ minNotional」，**没有任何一处读 `max_qty`**。
- **最小复现**：
  ```python
  spec = _spec(max_qty="1", qty_step="0.01", min_qty="0.01", min_notional="5")
  core = _core(strict=True, price_step=0.01, specs={"TESTUSDT": spec})
  res  = _run_core(core, [100.0]*6, stop=99.0)      # 6 根 15m，open=100，EOD 平仓
  res["trades"][0]["qty"]
  ```
- **实际输出**：`qty=43.13`（`maxQty=1`），`trades_count=1`，`rejected_orders=[]`。
  手算：`unit_risk = |100.03−98.9703| + (100.03+98.9703)×0.0005 = 1.15920`；
  `qty = 0.005×10000 / 1.15920 = 43.13`。
- **源码位置**：`trading_core/engine.py:517-570`（三道闸门只有 min_qty / min_notional）；
  `event_trend_v0_1/instrument_spec.py:120,236,249,351`（`max_qty` 解析后无消费者）。
- **影响范围**：所有带规格的入场（即事件趋势回测全量）。
  极端低价/低波动标的下按风险预算算出的数量可能超交易所上限 ⇒ **回测成交、实盘拒单**。
  注意 `_legacy_archive_v31/execution.py:391` 原本有 `qty > max_quantity` 校验，
  本次核心收敛把这条约束**丢了**（属回归，不是从未实现）。

### ★2 极低价格只挡「取整后 = 0」，不挡「取整后严重偏离原价」 —— 项1

- **现象**：`strict` 的三条闸门只要求 `post_round > 0`。价格 0.024 配 0.01 tick 时，
  取整把入场价抬到 0.03（**+25%**）、出场价压到 0.02（**−17%**），往返 −33.3%，
  全部计入 `gross_pnl`，而 `precision.run_valid` 仍为 `True`。
- **最小复现**：
  ```python
  core = _core(strict=True, price_step=0.01, stop=0.01)
  res  = _run_core(core, [0.024]*6)                 # 6 根 15m，open=close=0.024
  res["decisions"], res["trades"], res["precision"]["run_valid"]
  ```
- **实际输出**：`entry_fill=0.03（= 原价 ×1.250）`、`exit_fill=0.02（= 原价 ×0.833）`、
  `run_valid=True`。
- **源码位置**：`trading_core/fill.py:252-253`（只校验 `isfinite and >0`）；
  `trading_core/engine.py:886`（`run_valid` 仅由出场被拒触发）。
- **影响范围**：价格 < ~10×tick 的标的（SPACE/AIGENSYN/TRUTH 类）。
  这是 SPACE「零元卖出」的**残余形态**：零元已被挡住，但「价格被放大 25%/17%」仍静默通过，
  并直接进入盈亏与净值。
- 补充观测（A6）：价格 0.07 配 0.01 tick 时，3bps 滑点被 tick 放大成 ±14.29%
  （是名义滑点的 47.6 倍）。属规格选择问题，但说明「只用 bps 表达成本」在粗 tick 标的上失真。

### ★3 8787 的 OI 共振回测：默认 `price_step=0` + `strict=False` ⇒ 完全无 tick 约束，仍判 valid —— 项3/项5

- **现象**：`SignalParams.price_step: float = 0.0`，`SIGNAL_VALIDATION` 的下限也是 `0.0`
  ⇒ `0` 是合法值；`round_buy_price/round_sell_price/round_qty_down` 对 `step<=0` **直接返回原值**。
  于是 OI 生产回测的成交价 = `raw × (1±slip)`，一位小数都不取整。
- **最小复现**：
  ```python
  core = _core(strict=False, price_step=0.0)
  res  = _run_core(core, [100.0]*6, stop=99.0)
  res["trades"][0]["entry_price"], res["precision"]
  ```
- **实际输出**：`entry_price=100.03`（= 100×1.0003，未取整）、
  `price_steps={'TESTUSDT': 0.0}`、`spec_status='declared_no_spec'`、`run_valid=True`、
  `invalid_reasons=[]`。
- **源码位置**：`oi_resonance_v1/config.py:139`（默认 0.0）、`config.py:228`（校验下限 0.0）、
  `trading_core/fill.py:87,95,102`（`step<=0` 不取整）、
  `框架/backend/backtest_runner.py:948`（生产入口，不传 `instrument_specs`）。
- **影响范围**：8787「OI 共振」回测的**每一次**运行。`spec_status='declared_no_spec'` 已如实标注，
  但没有「无 tick 约束 ⇒ 不得正式通过」的阻断位（该路径也没有 `formal_pass_allowed`），
  因此这类 run 与「已按真实 tick 取整」的 run 在结果层面**同权**。
  同理，`instrument_specs` 未传 ⇒ minQty / minNotional / maxQty 在该路径**全部不生效**。

### ★4 非 strict 路径：0 价静默通过，NaN 抛非契约异常 —— 项3

- **现象**：`strict=False` 时 `quote_entry(raw_price=0.0, …)` 正常返回 `entry_fill=0.0`（不抛错）；
  `raw_price=NaN` 抛的是 `decimal.InvalidOperation`，**不是** `FillRejected`。
- **最小复现**：
  ```python
  a = SimulatedBarFillAdapter(slippage_bps=3, maker_fee_rate=2e-4, taker_fee_rate=5e-4, strict=False)
  a.quote_entry(raw_price=0.0, direction=1, price_step=0.01, stop_price=1.0).entry_fill  # 0.0
  a.quote_entry(raw_price=float("nan"), direction=1, price_step=0.01, stop_price=99.0)   # InvalidOperation
  ```
- **实际输出**：`raw=0 ⇒ entry_fill=0.0（无异常）`；`raw=NaN ⇒ decimal.InvalidOperation: px: non_finite`。
- **源码位置**：`trading_core/fill.py:261-270`（非 strict 分支无闸门）、
  `fill.py:58-76`（`_dec` 抛 `InvalidOperation`）、`oi_resonance_v1/execution.py:105`（strict 缺省 False）。
- **影响范围**：OI 生产回测。引擎级目前**偶然**被两层挡住：`prep_symbol` 拒非有限 OHLC
  （`engine.py:79-80`）、`check_entry` 的 `open_gapped_beyond_stop` 拦住 0 价入场；
  但「`except FillRejected`」捕不到 `InvalidOperation`，一旦上游放宽就会变成崩溃而非拒单。

## 三、次要缺口（报告准确性 / 潜在风险）

### ○5 `unclosed_positions` 会误报「仓位未平」 —— 项3

- **最小复现**：入场在 index 4，index 5 的 open/low = 0.004（gap 与 intrabar 出场都被拒），
  其后 close = 0.02 ⇒ EOD 以 0.01 成功平仓。
  ```python
  opens  = [0.02]*5 + [0.004] + [0.02]*3
  closes = [0.02]*5 + [0.02]  + [0.02]*3
  lows   = [0.02]*5 + [0.004] + [0.02]*3
  ```
- **实际输出**：`trades_count=1`、`open_positions_remaining=[]`、
  但 `precision.unclosed_positions=['TESTUSDT']`、
  `invalid_reasons=['exit_gap_fill_rejected:…','exit_intrabar_fill_rejected:…']`。
- **源码位置**：`engine.py:394`（`unclosed_positions.append` 后从不回撤）、
  `engine.py:888`（`sorted(set(unclosed))` 直接输出）。
- **影响范围**：任何「跳空出场被拒 → 后续正常平仓」的 run。`run_valid=False` 可以接受
  （该仓被多持有了，盈亏已被污染），但 `unclosed_positions` 这个**字段名与事实矛盾**，
  下游若据它判「仓位未平」会误判。建议（不代改）改为在收尾时按 `open_positions` 重算。

### ○6 非 strict 路径的 `slippage_split_ok` 是自证恒真 —— 项4

- **现象**：无 audit 时 `slippage_loss_pure = slippage_loss`、`rounding_loss = 0`，
  于是 `pure + round == total` **恒成立**，`slippage_split_ok` 恒为 `True`。
- **实际输出**（`strict=False, price_step=0`）：
  `rounding_loss=0.0`、`price_audit={'entry': {}, 'exit': {}}`、
  `slippage_split_ok=True`、`slippage_loss=2.587991383541603`。
- **源码位置**：`engine.py:582-591, 1000-1010`（`except` 分支把 pure 退回 total、round 归 0）。
- **影响范围**：OI 生产回测。该字段**不能**当作「取整损失已计量」的证据；
  若被写进验收结论即为假阳性。建议（不代改）在无 audit 时把分账字段置 `None`。

### ○7 订单类型约束未实现（潜在） —— 项2

- **最小复现**：子类化 policy 令 `entry_order_type()/exit_order_type()` 返回 `OrderType.LIMIT`。
- **实际输出**：`orders=[('open','LIMIT',None,'FILLED'), ('exit_eod','LIMIT',None,'FILLED')]`
  —— 没有 `limit_price` 的限价单被按「开盘价 + 滑点」成交。
- **源码位置**：`engine.py:232-242`（`_fill_order` 不看 `order_type` / `limit_price`）、
  `order.py:93`（`limit_price` 允许 None）。
- **影响范围**：当前生产只发 MARKET（入场）与 STOP_MARKET（出场），故**尚未造成损失**；
  但任何人新增限价单都会静默退化为市价撮合。同一缺陷使 STOP_MARKET 的 `stop_price`
  只作为审计字段存在，引擎不校验成交价与它的关系。

### ○8 负滑点 = 有利成交，事件趋势路径无参数校验 —— 项1

- **实际输出**：`SimulatedBarFillAdapter(slippage_bps=-30, strict=True).quote_entry(raw_price=100.0, direction=1, price_step=0.01, stop_price=99)` ⇒ `entry_fill=99.7 < 100.0`（有利）。
- **源码位置**：`fill.py:211`（构造无校验）、`engine.py:261`（无校验）；
  `event_trend_v0_1/config.py:EventTrendConfig` **没有 validate 方法**。
- **影响范围**：OI 路径由 `validate_exec_params`（`slippage_bps >= 0`）兜住；
  **事件趋势路径无任何校验** ⇒ 配置写错即静默产生有利成交（回测偏乐观）。

### ○9 空输入返回体形状不一致 —— 项3

- **实际输出**：`TradingCore.run({})` 的返回键里**没有 `precision`**，
  且 `max_drawdown_pct=0.0`（写死 0，与「缺结果一律 None」的项目约定相反）。
- **源码位置**：`engine.py:906-933`（`_empty_result`）。
- **影响范围**：任何以 `res["precision"]` 读运行有效性的下游，空输入直接 `KeyError`。

### ○10 第二套取整实现仍在生产代码 —— 项5

- **位置**：`框架/backend/strategies/wx_execution.py:1662,1669`
  （`step * math.ceil(px/step - 1e-9)` / `math.floor(px/step + 1e-9)`）。
- **影响范围**：375 标的臂的实盘/纸面信号执行链，不经 `trading_core`。

  该实现的 `price_step` 取自标的池字段（非写死 0.01），且 `_round_price_step` 无条件 floor（多空不分）。
