## 2. OI 因子到底怎么计算（`oi_resonance_v1/factors.py`）

权重唯一来源：`config.OI_WEIGHTS`（config.py:134-138）= `{level 0.50, price_div 0.25, mom_flux 0.25}`。

| 分项 | 定义 | 位置 |
|---|---|---|
| `f_oi_level_rank`（0.50） | **原始 `open_interest`** 的 `rolling(window, min_periods).rank(pct=True)`，**不 shift** | factors.py:203, 140-146 |
| `f_oi_price_div_rank`（0.25） | `div = sign(pct_change(close,12)) × pct_change(oi,12)` 的当期 rolling 分位 | factors.py:182-186, 204 |
| `f_oi_mom_flux_rank`（0.25） | `flux = pct_change(oi,48) × clip(vol/vol_ma(48), 0, 5)` 的当期 rolling 分位 | factors.py:188-197, 205 |
| `oi_chg_20` | `(oi − oi.shift(20))/oi.shift(20)`，**仅观察列，不进分数** | factors.py:176-179 |
| `oi_resonance_score` | `0.5·r_level + 0.25·r_div + 0.25·r_flux` | factors.py:210-213 |

窗口（实测打印）：
```
rank 窗口 = max(oi_chg_window+1, oi_rank_days×bars_per_day) = max(21, 90×24) = 2160 根（= 90 天 1h）
min_periods = min(2160, max(20, 24×7)) = 168 根（= 7 天）
```

缺失处理（符合"不伪造"纪律）：
- 无 `open_interest` 列 ⇒ `score = NaN` + `available = False` + `quality = "missing_open_interest"`。
  实测：**400 根序列全部 available=False，score 全 NaN**（未写 0 / 0.5）。
- 有 OI 但历史不足 ⇒ `quality = "partial_insufficient_history"`。
  实测：400 根合成序列中 score 仅 **185/400 根可用**（受 `oi_mom_flux_window=48` + `min_periods=168` 联合约束）。

### ⚠ 关键发现：**该因子默认对决策零影响**

`config.SIGNAL_FROZEN.oi_min_resonance = 0.0`（config.py:103），
`core.py:335` 的门禁是 `if p.oi_min_resonance > 0.0:` ⇒ **默认永不生效**。

实测对照（同一份 400 根数据）：

| 输入 | signal_counts |
|---|---|
| 带 OI | `{spring:12, donchian_breakout:9, lps_pullback:3, none:376}` |
| **删掉 OI 列** | `{spring:12, donchian_breakout:9, lps_pullback:3, none:376}` ← **完全相同** |
| 删掉 OI + 门槛设 0.5 | `{全 0}`，reject = `oi_factor_unavailable_fail_closed: 380` |

⇒ 当前"OI 共振"这四个字**没有进入任何决策路径**，只是记录在事件里的一个披露字段
（而且因为可用性不足，事件里 `oi_resonance_score` 常常是 `null`）。
一个名字里有 OI、行为上不含 OI 的策略，不是"参数待调"，是**因子未启用**。

## 3. Wyckoff 因子怎么计算

### 3.1 新包（`oi_resonance_v1/core.py`）：两个"当根即时判定"信号

| 信号 | 条件 | 位置 |
|---|---|---|
| `spring`(1) | `l[i] < dc_low_prev[i]` ∧ `c[i] > dc_low_prev[i]` ∧ `c[i] > o[i]` | core.py:355 |
| `sc_reversal`(2) | `v[i] > 2.0×vol_ma_prev(20)` ∧ `l[i] < dc_low_prev[i]` ∧ `(h−l) > 1.5×atr` ∧ `lower_wick ≥ 0.5×(h−l)` | core.py:346-350 |

**没有**"威科夫因子"这种分数。威科夫在这里只有这两个布尔条件。

### 3.2 旧 WX（`wx_donchian_wyckoff.py`）：**事件状态机**，语义完全不同

- Spring：箱体宽度 < 4×ATR ∧ 严格跌破 L20 ∧ 收回 ∧ `close_pos > spring_close_pos` ∧
  `quote_volume > 1.5×箱体均量` ∧ 跌破深度 < 0.6×ATR；**锚点建立后需 1–3 根内 close > 冻结中线才算确认**，
  期间 `low < detection_low` 即失效（wx_donchian_wyckoff.py:252-300, 357-415）。
- SC：close < 含当根 20 根均价 ∧ 放量 > 2×前 20 均量 ∧ `close_pos > sc_close_pos` ∧
  新低超过 `sc_newlow_pct` ∧ **需 1–5 根内 close > 恢复目标才算确认**（同文件 303-349）。
- 还有"同 bar 不得确认"、"同类新检测不覆盖锚点"、"解析后下一根才允许新建"等规则。

⇒ **新包是"当根即出信号"，旧 WX 是"检测 → 等 1–5 根确认 → 出信号"。**
两者对同一根 K 的判定时点相差 1–5 小时，且新包**没有**放量/收盘位置/深度/箱体约束。

### 3.3 旧 v3.1 的 M4/M5/M6 因子在新包里不存在

旧 `WyckoffMaster/factors.py` 的 M4（OI 变化 90 日分位排序）、M5（全网账户比 30 日分位 >90% 过滤）、
M6（大户持仓比 30 日 Z 降序排序）在新包中**完全未实现、未继承**，
`config.NOT_INHERITED`（config.py:48-54）已逐条声明。这一点**披露正确、无冒充**。

## 6. 入场条件

**新包**（`execution.py:481-573`，相位 C）：
1. 该 15m bar 上有待开仓信号（由 `confirm_time` 映射而来）；
2. 该标的当前无持仓，否则 `duplicate_symbol_active` 拒；
3. 并发持仓 < `max_concurrent_trades`(=3)，否则拒；
4. `entry_fill = round_buy(open×(1+3bps))`，若 `entry_fill ≤ stop_ref` ⇒ `open_gapped_beyond_stop` 拒；
5. `mtm = cash + 未实现` > 0；
6. 组合本金风险：`max_portfolio_risk(4%) × mtm − 当前风险 ≥ risk_per_trade(0.8%) × mtm`；
7. 名义仓位上限：`mtm × 40% × 2.0 − 当前名义 > 0`；
8. `qty = min(0.8%×mtm/unit_risk, mtm×2/entry, avail_notional/entry)`。

**旧 v3.1**（`execution.py:413-526`，`plan_entry`）：模式校验 → short 显式拒单 → 持仓数上限(10) →

## 11. 信号冲突

**新包同根优先级**（core.py:317-380）：
```
⓿ fresh breakout 登记（在因子门禁之前）
① 因子门禁（oi_min_resonance > 0 时才生效）
② sc_reversal  → ③ spring  → ④ donchian_breakout  → ⑤ lps_pullback  → ⑥ short(默认关)
```
**实测确认优先级**：构造一根同时满足 SC 与 Spring 的 bar ⇒ `signal_name = "sc_reversal"`；
把 `enable_sc=False` 后同一根 ⇒ `"spring"`。**SC 先于 Spring 成立。**

**但有两个容易被忽略的语义**：

1. **优先级只在"高优先级被接受"时才阻断低优先级。**
   代码是 `if _accept(...): continue`；`_accept` 返回 False（止损被拒）时**不 continue**，
   会继续往下判 Spring / 唐奇安 / LPS。
   实测：把 `sc_range_atr_mult` 抬到 99（SC 条件不成立）⇒ 同一根落到 `spring`。
   ⇒ 存在"**首选项被风控拒绝后，改用次优信号**"的路径。
2. `reject[i]` 是单值字符串，会被后续尝试**覆盖**；同根多次拒绝只留最后一次原因。

**旧 WX 冲突顺序完全不同**：`Spring → breakout → retest`（core.py:11, 482），
且 base 与结构重合时**执行标签 base 优先**、保留全部 `source_masks`（wx_donchian_wyckoff.py:523-535）。

## 12. 同一根 K 是否可能重复信号

| | 结论 | 依据 |
|---|---|---|
| **新包** | **不会** | 单循环 + 命中即 `continue`；`signal` 是**单一整数编码**（0/1/2/3/4）。实测 400 根：无非零多信号、无 >4 值 |
| **旧 WX** | 同根最多 1 条 long + 1 条 short | wx_donchian_wyckoff.py:506-546 |
| **旧 live 层** | `signal_uid` 幂等 + 结构提示同刻同 kind 抑制 | live_signal_engine.py:531-558 |

补充：新包的**同一根突破**会在后续 bar 再产生 `lps_pullback`（回踩当根）——
这是**不同 bar 的不同信号**，不算重复；但执行层会因 `duplicate_symbol_active` 只保留先到的那笔。

## 13. 是否存在未来数据泄漏

**逐项核验：没有严重前视。** 但有两处口径必须盯住。

### 13.1 已核验为因果的部分

| 项 | 判定 |
|---|---|
| `dc_high_prev` / `dc_low_prev` / `exit_*_prev` | `rolling(n).shift(1)` ✓（core.py:273-276） |
| `atr`（当根收盘） | 用于当根止损，收盘后可得 ✓（core.py:268，与旧 WX 一致） |
| `exit_low_curr`（不 shift） | 映射到"信号 bar 收盘后的**下一根 15m**"才生效 ✓（execution.py:181, 312-329） |
| `confirm_time = 收盘`，成交在 `≥收盘时刻` 的首根 15m 开盘 | ✓ 实测 `confirm_time == 开盘+3600`，且 `confirm_time ≤ 开盘` 恒 False |
| 期末强平用最后一根 close | 是窗口末，非前视 ✓（execution.py:620） |
| `_current_pct_rank` 不 shift | 当根收盘后该分位已可得，非未来函数 ✓（factors.py:140-146） |

### 13.2 ⚠ 需要盯的两处

**(a) OI as-of 的同刻边界（最多 5 分钟口径乐观）**

- 回测对齐规则：`pos = searchsorted(oi_ts, close_ms, "right") − 1`
  ⇒ 取 `ts <= close_ms` 的最近一条（backtest_runner.py:389）。
- 这会取到"**5m 桶起点恰好 == 1h 收盘时刻**"的那一条。
- 而本项目 5m OI 的落库纪律是：**只有 `ts + 5m <= now` 的桶才写 `period='5m'`**
  （realtime_collector.py:1014-1021）⇒ 该条在 `ts+5m` 之前**根本不在库里**。
- ⇒ 回测用到的这条 OI，实时读库时**尚不可见**。
- **当前无实际影响**（因子门禁默认关闭）；**一旦 `oi_min_resonance > 0`，就变成真实分歧**。

**(b) 预热校验阈值 < 因子真实可用起点**

- 回测 `need_warm = max(20, min_periods) = 168`（backtest_runner.py:347-354）。
- 但 `f_oi_mom_flux_rank` 需先有 `oi_mom_flux_window = 48` 根，
  rank 再要 168 个有效值 ⇒ **真实可用起点约 215 根**（实测 400 根序列仅 185 根可用，吻合）。
- ⇒ 若恰好按 168 根预热，交易窗前 ~47 根的 `score` 仍为 NaN（默认门槛关，不阻断）。

### 13.3 附带：新包不做时间网格连续性校验

实测：把序列中间**挖掉 5 根**后，`compute_signals` **不报错、照常出信号**
（`{spring:2, donchian_breakout:11, lps_pullback:3}`）。
- 旧 WX 在缺口处**重置段与 240 根预热**（`_segments`，wx_donchian_wyckoff.py:142-167，A-09）。
- 回测 runner 用 `_closed_contiguous` 强制"连续 + 全窗覆盖"，缺口即 `RuntimeError` ⇒ **回测侧安全**。
- 但 `registry_entry.run`（live 入口）**只 dedup、不查连续性** ⇒ 若 live 真接上而数据有洞，
  Donchian/ATR/滚动窗口会静默变形，规则与回测分叉。

## 16. 缺陷清单（按对"跨 Runtime 一致性"的破坏程度排序）

### P0 —— 直接使"一致性"命题不成立
1. **回测与实盘是两套策略 + 两套执行核心 + 两套账户参数。**
   `live_signal_engine.oi_resonance_events_for()` 与 `exec_bridge.run_portfolio_execution`
   **均为零调用方的死代码**。注册表声称的"当前策略"与实际在跑的臂不是同一个东西。
2. **成交时刻口径相差 15 分钟**（新包在收盘那根 15m 开盘成交；旧核心在下一根 15m 开盘成交）。

### P1 —— 会在"接上线之后"立刻变成分歧
3. **OI 因子默认对决策零影响**（`oi_min_resonance=0`）。实测带 OI 与删掉 OI 的信号数完全相同。
   策略名与行为不符；"OI 共振"这一说法目前**未经任何检验**。
4. **新包无时间网格连续性校验**，而 live 入口不校验输入 ⇒ 有洞的数据会静默改变 Donchian/ATR/滚动窗口。
5. **`registry_entry.run` 不接受参数覆盖**（含 `price_step`），回测可覆盖 ⇒ 覆盖后必然分叉。
6. **事件字段缺 `conditions` / `available_at` / `source_id` / `market` / `exits`**，
   且事件只带合成 `score`、不带三个原始分项 ⇒ **无法从事件层复核入场条件、出场与因子**。
7. **新执行核心缺项**：无到期、无回撤锁定、无参与率上限、无现金预留、无合约规格（min_qty/step/min_notional）校验。
   这不是"更严/更松"，是**风控面不等价**，两侧的风险预算不可比。

### P2 —— 口径与卫生问题
8. **OI as-of 同刻边界**：`ts <= close_ms` 会取到落库规则下"尚未可见"的 5m 桶（≤5 分钟乐观）。
9. **预热校验阈值 168 < 因子真实可用起点 ~215**。
10. `registry_entry._bars_to_frame` 的 `close_time = open + 1h`，≠ 币安口径 `open + 1h − 1ms`（当前惰性字段）。
11. **高优先级信号被风控拒后不阻断低优先级**，会落到次优信号；`reject_reason` 被后续尝试覆盖。

## 18. 给"证明一致性"这件事的最小可执行清单

要让"同一套规则在不同 Runtime 一致"这句话成立，按依赖顺序至少需要：

1. **选定唯一策略身份**：把 `live_worker` / `live_signal_engine` 的 `ARMS` 从 3a–3d 切到
   `oi_resonance_events_for`，或明确宣布新策略只做研究、不进实盘 —— 二选一，不能悬着。
2. **统一成交时刻口径**：新包的 `confirm_time = 收盘` 与旧核心的 `+15 分钟` 必须收敛到同一规则。
3. **统一执行核心**：实盘改调 `run_portfolio_execution`（或反之），并补齐新核心缺的
   到期 / 回撤锁定 / 参与率 / 现金预留 / 合约规格 —— 否则风控面不等价。
4. **统一参数来源**：`registry_entry.run` 要能接受与回测同一套覆盖参数（含 `price_step`）。
5. **补事件字段**：`conditions` / `available_at` / `exits` / 三个 OI 原始分项。
6. **补输入校验**：新包加网格连续性校验（或复用旧 `_segments` 语义），live 与回测同一套输入契约。
7. **决定 OI 因子的地位**：要么 `oi_min_resonance` 设成有意义的门槛并接受 fail-closed 后果，
   要么把"OI 共振"从策略名与描述里去掉。当前状态是最差的一种：**名字里有、代码里有、决策里没有。**
