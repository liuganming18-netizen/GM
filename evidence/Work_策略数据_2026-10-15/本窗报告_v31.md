## 2. 物理隔离：怎么做到的

需求是「不能把含 Holdout 的文件整读一遍再过滤，然后声称零读取」。逐数据集的实际来源：

| 数据集 | IS 窗口来源 | Val 窗口来源 | 是否触碰跨界文件 |
|---|---|---|---|
| OHLCV 1h/4h/15m | 冷档**年分片** `candles/.../{2021..2024}.parquet` | 冷档 `2024`(10-12月)+`2025`，+ raw 月包 `2026-01/02/03`，+ **官方 daily 日包** `2026-04-01..14` | 否 |
| OI + 4 比率 | `raw_oi_metrics` 官方**日包**（按日期精确选取 ≤2024-12-31） | 同源日包，日期 ≤ `2026-04-14` | 否 |
| 资金费 | raw `fundingRate` **月包** ≤ 2024-12 | raw 月包 ≤ 2026-03，+ 官方 `fapi/v1/fundingRate` 尾段 `2026-04-01..14`（含真实 markPrice） | 否 |
| 结算 mark | raw `mark1h` 月包 ≤ 2024-12 | raw 月包 ≤ 2026-03，+ 官方 daily `markPriceKlines`（尾段与内部空洞） | 否 |

**明确回避的跨界来源**（均未整读）：
- `data/archive/parquet/**/2026.parquet`（实测覆盖到 2026-09-14，跨界）
- `data/archive/parquet/funding/binance/um/*/funding.parquet`（单文件 2020→2026-09，跨界）
- `raw/{1h,4h,15m,mark1h,funding}/*/*-2026-04.zip`（月包跨界）
- `market_v2.sqlite3` 全表 / 全时段扫描

**为什么 2026-04 要用日包**：Holdout 起点是 2026-04-15，而 2026-04 月包覆盖整月（含 Holdout）。官方 `data.binance.vision` 的 **daily** 日包不跨界，故 Val 尾段 14 天全部改用日包（K 线 + mark），funding 因官方无日包改用定向 API。

## 5. 已知缺口（如实列出，不伪造）

1. **mark1h 内部空洞（已补）**：本地 raw mark1h 月包存在整天空洞（如 BTCUSDT 2022-07-31 / 2022-10-02 / 2023-02-24）。已用官方 daily `markPriceKlines` 补齐 IS 共 **6,144 小时 / 119 币**；Val 无内部空洞。
2. **结算 mark 缺口（官方缺失则保持 null，不伪造）**：
   - 用官方 `fapi/v1/fundingRate` 对确实缺失的结算事件做定向补齐：Val 补齐 **1,623 条 / 37 币**（最终 Val 结算 mark **0 缺失**）；IS 补齐 10 条。
   - IS 余 **24 条**仍缺：结算时刻早于该币 mark 数据首小时，且官方 API 对该时刻返回**空 `markPrice`**（实测 APTUSDT 2022-10-18 16:00 官方 `markPrice` 为空串）。**未补 0、未插值、未用普通成交价冒充**。
   - 3 个中文名符号（币安人生/我踏马来了/龙虾 USDT）无 mark1h 归档，其真实结算 mark 已由官方 API 补齐。
3. **4 个符号无 Val 尾段日包**（AIGENSYN/CHIP/GENIUS/OPG USDT）：均为 2026-04-15 之后才上线，Val 窗口内本无数据，属正常。
4. **3 个中文名符号官方日包 404**：vision 对其 K 线/mark 日包返回 404（本地有月包）。其 OHLCV 已由冷档年分片提供；Val 尾段 2026-04-01..14 的 K 线因日包不可得而缺失（已计入覆盖差异）。
