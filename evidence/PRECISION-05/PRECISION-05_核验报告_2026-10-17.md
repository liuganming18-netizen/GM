### 3.3 算术复现：为什么能确定是 `0.01` 步长

对每条腿，用运行时的取整规则（`fill.py`：买 `step*ceil(px/step-1e-9)`、卖 `step*floor(px/step+1e-9)`）反推：

| 腿 | 基准价 | 基准 | 能复现该成交价的步长 |
|---|---|---|---|
| SPACE 开 | 0.009718 | bar open | 0.01 / 0.005 / 0.001 |
| SPACE 平 | 0.00677965 | stop | 0.1 / 0.05 / 0.01 |
| AIGENSYN 开 | 0.02125 | bar open | **仅 0.01** |
| AIGENSYN 平 | 0.01899 | stop | **仅 0.01** |
| TRUTH 开 | 0.015693 | bar open | 0.01 / 0.005 |
| TRUTH 平 | 0.012475 | stop | 0.01 / 0.005 |
| COTI 开 | 0.06228 | bar open | **仅 0.01** |
| COTI 平 | 0.08568 | stop | **仅 0.01** |
| BNB 开 | 317.68 | bar open | 0.01 / 0.005 |
| BNB 平 | 290.2438 | stop | 0.05 / 0.01 |
| ORDI 开 | 47.768 | bar open | **仅 0.01** |
| ORDI 平 | 62.078 | bar open | 0.05 / 0.01 |

单条腿往往有多个步长都能复现（粗步长在小价格上会被 `ceil` 抬到同一格），**所以要求交集**：

> **能同时复现全部 12 条腿的步长 = `{0.01}`，唯一一个。**

这不是"看起来像 0.01"，是"只有 0.01 能把这 12 个成交价全部算出来"。

### 3.4 结论：分三层说，不含糊

**（一）已确认 —— 成交价是怎么算出来的（算术层）**
12/12 腿的成交价 = 该 bar 的 `open`（开仓 / `max_holding`）或该单的 `stop_price`（`intrabar_stop`），乘以滑点 `1±0.0003`，再按 `0.01` 步长「买 ceil / 卖 floor」。步长交集唯一为 `0.01`。
**这不是撮合错误** —— 撮合错误不会产生「恰好等于取整函数输出」的价格。这是**取整参数用错**。

**（二）已确认 —— run 里没有规格（配置层）**

| 检查 | 结果 |
|---|---|
| run 目录是否有 `instrument_spec.json` | 6/6 **都没有** |
| `inputs.json → fingerprints.config.params` 是否有 `price_step` / `tick_size` / `instrument_spec` | 6/6 **都没有**（`config_has_price_step=False`） |
| run 产物（`orders` / `fills` / `decisions` / `ledger` / `summary`）是否记录所用步长 | **一处都没有**（全文搜 `price_step`/`tick` 无命中） |

也就是说：**事后无法从 run 自身读出它用了什么步长**，只能像 3.3 那样从算术反推。

**（三）证据不足 —— 谁把 `0.01` 传进去的（调用层）**

`inputs.json` 里有完整的**代码指纹**（每个文件一个 sha256），我拿它跟当前磁盘和 `git HEAD` 三方对照：

| `trading_core/fill.py` | `15e29dd0…` | 不同 | **完全相同** | **能**（`git show HEAD:` 取回，已存 `运行时代码/fill.py.HEAD`） |

两个关键结论：

**（四）额外发现：run 自己的自检是"通过"的**
