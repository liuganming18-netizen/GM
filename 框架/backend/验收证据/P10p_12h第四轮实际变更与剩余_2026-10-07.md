## 退回项 ③：全池 OI 美元金额 → **已修复并验证端到端**

**根因（实测）**：`oi_history` 币安 528 标的最新行 `oi_usd` **全为 NULL**
（`binance_rows=95646`、`distinct_symbols=528`、`oi_usd IS NOT NULL` 行 = **0**）；
旧代码用 `/fapi/v1/openInterest`（**官方无美元额**）。

**变更**（`realtime_collector.py`，本轮独占文件）：
- 币安 OI 源改为 `binance.oi_hist` = `/futures/data/openInterestHist?symbol=..&period=5m&limit=1`，
  **同一行**同时给 `sumOpenInterest`（总量）与 `sumOpenInterestValue`（美元名义额）；
  `source="binance.fapi.openInterestHist"`；数量与金额**共用同一行、同一时点**。
- 端点用 `ENDPOINTS.setdefault` 在采集器内**幂等登记**（不改共享 `gateway_ext.py`）。
- **失败不写 0、不用数量×价格替代**：失败只计数、不落行 → 保留上一轮值（陈旧），可如实区分。
- 请求数**不变**（仍 1 次/标的 × 528），不增加预算占用、不动 K 线采集（K 线走 WS）。

**实测（全池轮巡已完成，round id=4199）**：
- 有界活体探测（8 标，走同一网关 profile）：**8/8 双字段齐全**
  （BTC `sumOpenInterest=95776.696` / `sumOpenInterestValue=7948938996.17`）。
- **实测全池轮巡耗时 756.6s**（`started_at=1791387144992` → `finished_at=1791387901542`），
  **成功 518 / 失败 10**（网络抖动 + 预算竞争；与改动前 692–701s / 失败 3–70 同量级，非回归）。
- **覆盖终值（库内 528 标池）**：
  | 口径 | 数量 |
  |---|---|
  | 池内标的 | 528 |
  | 有最新行（`latest_has_row`） | 528 |
  | **有美元金额（`oi_usd` 非空）** | **518** |
  | 其中 新鲜（≤20min） | 513 |
  | 其中 陈旧（>20min） | 5（含 1 个官方端点只返回 ~2.3 天前桶的标的：`1000000BOBUSDT`） |
  | 无美元金额（`row_without_usd`） | 10（本轮失败 → 保留旧值，**未假造 0**） |
  | 池内无行（`pool_missing_row`） | 0 |
- **API 端到端**：`GET /api/v1/markets` 币安 **526** 项中 `open_interest_usd` 非空
  **由 0 → 516**，10 项仍空；样例 `0GUSDT` qty=36538520 / usd=10978544.22 / t=15:40Z。
- **轮巡节奏（如实）**：`oi_interval=600s`，但单轮实测 756.6s，故 `oi_loop` 完成后再 `wait(600s)`，
  实际节奏约 **1356s（≈22.6min）**；20min 新鲜阈值因此偏紧，`oi_time` 字段已逐条给出真实时点。
- 证据：`验收证据/P10n_...json`、`P10q_12h_全池OI金额_轮巡完成覆盖_2026-10-07.json`、`logs/_p10_oi_measure.py`、`logs/_p10_oi_final.py`

**口径说明（数量/金额各自时点）**：`openInterestHist` 的 `timestamp` 为 **5m 桶起点**，
数量与金额取自**同一行**，故共用该时点；旧 `binance.oi` 用服务器毫秒时间，
新桶起点 ts 恒大于旧行同桶 ts → `MAX(ts)` 一轮后即取到含 usd 的新行。
表 `oi_history` PK 含 `ts`，5m 桶稳定 → 重复轮巡**覆盖同一行**，表不再无界增长。
