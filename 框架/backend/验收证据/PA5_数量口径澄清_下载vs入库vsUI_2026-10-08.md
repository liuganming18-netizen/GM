# PA5 数量口径澄清：下载 vs 入库 vs UI 可见 2026-10-08

用户问：**「你这个数量是下载了的数量还是导入 UI 界面的数量？」**

**答：都不是"下载量"，是"已导入库"的量 —— 也就是后端 API 的数据源。**
但它**也不等于 UI 界面当前画出来的量**（UI 每周期只请求最近 60 根）。三个口径必须分开。

---

## 1. 三个口径的实测对应关系（以 5m 为例）

| 层 | 5m 数量 | 出处 | UI 能否看到 |
|---|---|---|---|
| **① 下载** | **18,921 个 ZIP 文件** | `历史下载/` 磁盘归档 | **看不到**（未入库） |
| **② 入库（我报的数字）** | **24,495,942 根** | `market.sqlite3` 的 `candles` 视图 | 通过后端 API 可读 |
| ③ API 单次可返回 | **≤ 2,000 根/周期** | `adapter.py` 分页上限（实测 `limit=5000` 仍只回 2000） | 受此上限约束 |
| ④ UI 实际渲染 | **60 根/周期** | `前端实现-AIStudio/src/api/useMarketData.ts:45` `DETAIL_BAR_LIMIT = 60` | 图表只画最近 60 根 |

## 2. 代码证据（我报的数字 = API 数据源）

- `adapter.py:50` → `DB_PATH = MARKET_DB or <PROJECT_ROOT>/data/market.sqlite3`
- `adapter.py:70` → `STORE = MarketStore(DB_PATH)`
- `adapter.py:1483` → `v1_candles()` 调 `STORE.candles(exchange, market, mid, tf, 0, None, fetch_n)`
- `candles` 视图定义 → `SELECT v.* FROM candle_versions v JOIN candle_heads h USING(...)`
  ⇒ **`candle_heads` 的计数 == API 能读到的根数**（我用的就是它）
- `public_market_read.py:33` → 同一 `DB_PATH`
- 项目内**只有这一个** sqlite 库（`data/market.sqlite3`）
- 前端 `useMarketData.ts:381` → `` `${marketPath(ex,mk,'candles')}?timeframe=${tf}&limit=${DETAIL_BAR_LIMIT}` ``
  ⇒ UI 走的就是同一个 `/api/v1/markets/{ex}/{mid}/candles`

## 3. 实时 API 实测（后端 8787 在跑，PID 32913）

```
GET /api/v1/markets/binance/BTCUSDT/candles?timeframe=1d&limit=5000
  → 返回 2000 根，最早 2021-04-16T00:00:00Z，最新 2026-10-06T00:00:00Z
GET /api/v1/markets/binance/BTCUSDT/candles?timeframe=5m&limit=5000
  → 返回 2000 根，最早 2026-09-30T20:00:00Z，最新 2026-10-08T03:25:00Z
GET /api/v1/markets/binance/BTCUSDT/candles?timeframe=1m&limit=5000
  → 返回 2000 根，最早 2026-10-06T09:21:00Z，最新 2026-10-08T03:31:00Z
```

- 1d 返回的 `source_url` 是官方归档 ZIP（`data.binance.vision/.../BTCUSDT-1d-2026-10-06.zip`）
  ⇒ 证实 **API 读的是"已导入库的归档数据"**，不是现抓。
- **2000 根是接口上限**：5m 明明库里有 ~1 年（约 105,120 根），接口一次也只给 2000 根（≈7 天）。
- 顺带：`/api/data/status` 端点 45s 超时未响应（后端自报全量统计很重），K 线端点正常。

## 4. 结论

1. 我上一轮报的「库内根数」= **② 入库量**，是 **API 数据源**口径，**不是** ① 下载量。
2. 5m 有 **15,227 个 ZIP 已下载但未入库** —— 这部分 **UI 绝对看不到**。
3. 即便入了库，**UI 图表每周期也只显示最近 60 根**；即使前端把 `limit` 调大，**API 也只给 2000 根**。
4. 所以"UI 界面看到的数量"是一个**被 60 / 2000 双重封顶**的口径，**不能**用来衡量历史完整度。
   **衡量历史完整度只能用 ② 入库量 vs 应有量**（即 PA4 的 `data_completion_pct`）。
