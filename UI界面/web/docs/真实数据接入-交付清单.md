```ts
  const b = buckets[i];
  if (b.snapshotMs !== null && b.snapshotMs <= cutoff) { ref = b; break; }
}
if (!ref || ref.snapshotMs === null) return null;
const spanHours = (last.snapshotMs - ref.snapshotMs) / HOUR_MS;
if (spanHours < 24) return null;   // 不足 24h 就不算 24h 净变
```

|---|---|---|---|---|
| A | 23 h | 23.10 h | `null` | ✅ |
| B | 26 h | 26.50 h | `{percent: 30, spanHours: 26.5}` | ✅ |
| C | **24 h** | **23 h 20 m** | **`null`** | ✅ **旧逻辑会误报** |

### 1.4 Fix 4 · 费率口径

#### (a) 主表「资金费率 (8h)」（`TokenTable.tsx`）

- **标签与徽章样式原样保留**（`bg-emerald-500/10 text-emerald-400 border border-emerald-500/20` ↔ rose 变体，位置、字号、结构均未动）。
- 仅**值**改为门控输出：

```ts

{fundingOk && token.fundingRate != null ? fmtSignedPercent(token.fundingRate * 100, 4) : '—'}
```

**两法互证（本轮重新取证）**：

| 口径 | 方法 | 实测分布 |
|---|---|---|
| A 法（行内前瞻） | 全池 **549** 条 `next_funding_time − funding.latest_funding_time` | `12h×417`、`16h×124`、`8h×2`、`24h×5`、`21h×1`（**5 种**） |
| B 法（历史间隔） | 抽样 **200** 条，费率历史相邻 `event_time` 间隔的众数 | `4h×151`、`8h×48`、`1h×1`（**3 种**） |
| 稳定性 | 窗口内所有间隔是否一致 | **199 / 200** 完全稳定 |

**同一合约两法互相矛盾 = 200 / 200（100%）**。逐条样例：

| 合约 | A 法（行内） | B 法（历史） | 历史是否稳定 |
|---|---|---|---|
| `binance/BTCUSDT` | **16 h** | **8 h** | 是 |
| `binance/0GUSDT` | 12 h | 4 h | 是 |
| `binance/1000PEPEUSDT` | 16 h | 8 h | 是 |
| `binance/1000BONKUSDT` | 12 h | 4 h | 是 |

BTC 精确换算：`funding.latest_funding_time = 2026-10-05T16:00:00Z`、`next_funding_time = 2026-10-06T08:00:00Z` ⇒ A 法 16 h；而费率历史相邻间隔为**纯 8 h**。
→ A 法被证实为「`next_funding_time` 是 8h 对齐时钟、`latest_funding_time` 是上一次实际结算」的产物，**不是周期**。

**结论**：前端运行时只拿得到行内两个时间戳、**没有费率历史调用**，因此**界面侧无法确认任何一条是 8h** ⇒ 该位空值。
（离线分析显示 B 法下 48/200 为稳定 8h、151/200 为 4h；若要按此口径输出，需前端新增「费率历史」请求，与「不增删」冲突 ⇒ 未做，已列入 0.3 第 2 条待裁决。）

页面实测：表头 `7. 资金费率 (8h)` 保留，前 8 行取值全为 `—`。

#### (b) WebSocket 值槽改为「数据龄」（`NavigationSidebar.tsx`）
