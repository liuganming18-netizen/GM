页面已由手写 SVG K 线整体替换为 **TradingView Lightweight Charts™ 官方实现**（本地 npm 依赖，不加载远程 Widget，不替换行情数据源）。

## 2. 本轮（第二次浏览器复测后）修复项

### 2.1 切周期竞态 → 改用 React 生命周期原生隔离（不再自造切换协议）

**问题**：在 30m 历史窗里点 1h 再点回 30m，30m 恢复到了 `09-26 08:00–10-01 07:30`（不是它自己的窗口）。原因是旧周期的图表实例在同一容器上继续存在，其时间轴回调/去抖上报在切换期间落到了新周期。

**修复**：给两个官方图表实例绑定 React `key`，让切周期**原生卸载旧实例、挂载新实例**，新实例再从独立缓存恢复自己的视窗。

```tsx
<CandleVolumeChart key={viewKey} … />
<OiLineChart       key={`${viewKey}:oi`} … />
```

旧实例的官方图表、内部观察器、事件订阅、去抖定时器全部走既有 cleanup 路径销毁（`useChartLifecycle` 的 effect 清理：清定时器 → 解订阅 → marker detach → `chart.remove()`）。
同一周期内的实时刷新 `viewKey` 不变 ⇒ **实例不重建**，仍走增量 `update()`。

### 2.2 视窗上报**绑定所属 viewKey**，父组件按当前视图键拒绝迟到报告

```ts
onViewportChange: (viewport: ChartViewport, viewKey: string) => void
```

`viewKey` 在 **调度时刻**捕获（不是定时器触发时读取），父组件 `handleViewportChange` 首行即 `if (key !== viewKeyRef.current) return;`。
双保险：旧周期的报告即使侥幸存活，也**不可能**落到新周期的视窗缓存上。

### 2.3 取消过早的 `reportNow`：落位后由**原生可见范围事件**驱动去抖读取

**问题**：状态位显示 `视窗 10-05T20:37–10-08T13:00`，而画布刻度已是 `10-04～10-07` —— 两者互相矛盾。
**根因**：官方库的 `setVisibleRange` / `fitContent` 是**异步生效**的；调用返回后立刻 `getVisibleRange()` 读到的是**落位前**的旧范围。

**修复**：删除 `reportNow`（立即读取）。落位完成后只调用 `endProgrammatic()`（清除静默窗 + 取消待发上报），再交给 250ms 去抖上报 —— 由原生范围事件驱动，读取时范围已落实，状态位与画布一致。

```ts
// 落位后：不读取范围，只放开静默窗
lifecycle.endProgrammatic();
lifecycle.scheduleReport();
```

### 2.4 恢复门闸**只由真实输入事件解除**

删除了「与恢复目标偏离较多 ⇒ 自动认作真实用户变化」这条推断式解除路径。
现在程序化落位（首屏 `fitContent`、数据重置、历史补齐后的重新落实）产生的**任何**范围都写不进用户视窗缓存。

门闸解除点只剩 2 处：
1. 该视图键本无恢复目标（首次展开，原版行为）；
2. 真实输入事件（`onWheel` / `onPointerDown` / `onTouchStart` → `markUserViewport`）。

### 2.5 其他配套修正

| 项 | 内容 |
|---|---|
| 时间窗同步单向 | 只有 `leader`（K 线）驱动 `follower`（OI）；OI 的程序化范围变化**永不**反向覆盖主图。用户主动操作 OI 时开放 500ms「用户驱动窗口」保持联动 |
| 程序化静默窗 | `viewChanged`（整表重置）时进入 400ms 静默窗，重置期的中间范围不上报；**实时增量刷新不进入**，视窗读数不停更 |
| 首次落位守卫 | 必须等本图**确有真实时间点**才做首次落位（空时间轴调用官方 API 会抛 `Value is null`，实测白屏根因） |
| 恢复判据放宽 | 恢复区间只要合法即**原样落位**，不夹到本图数据域、不自造范围；域外自然显示空白。旧判据要求「完全落在已加载域内」，首屏只有一页时必然被拒 → 退回 `fitContent` → 用户视窗被顶掉 |
| 自动补更早历史 | 恢复区间起点早于已加载最早根且本地还有更早历史 ⇒ 逐页补；补到覆盖后按真实 UTC 时间原样重新落实 |
| 模块级会话缓存 | 视窗与已加载历史提到模块级（键 `${tokenId}:${tf}`），收起（卸载）后不丢；历史上限 24 个键，超出按最早写入淘汰 |
| 句柄守卫 | `ChartHandle` 新增 `visibleRange()`：已销毁/无时间点 → `null`，绝不抛错（切周期会原生卸载实例，父组件不能去猜实例是否还有效） |
| 脏时间加固 | `toChartSeconds` 对非有限/非正输入一律回 `0`，不让 `NaN` 时间透传进官方库 |

## 7. 已知限制（如实列出，不掩饰）

1. **未收盘根用颜色 + 文字区分**：官方库没有虚线蜡烛样式，故未收盘临时层使用单根独立琥珀色（`#f59e0b`）+ 页面「未收盘 <UTC 时刻>」标签，不并入已闭合历史、缺口判定与指标统计。
2. **OI 缺口用多段 `LineSeries`**：官方 `WhitespaceData` 不能断线（`LinePaneViewBase` 对相邻有效点持续 `lineTo`），故 `hasGap`/空值处按段拆分序列；段数随数据变化增删，复用同一价格轴，仅最后一段显示最新值标签。
3. **OI 采样节奏不规则**：真实样本间隔中位数约 1045s（含 600s 与 32400s 缺口），时点落在任意秒。共享网格只做「时间点并集 + 纯 whitespace 锚点」，**不重采样、不聚合、不补值**。
4. **价格轴等宽用 `PriceScaleOptions.minimumWidth`**：按两图实际标签宽度取最大值回写，窗口尺寸变化时重新对齐。
5. **恢复门闸在「跟随最新」目标下不再钉住窗口**：`followLatest === true` 时恢复后交给官方 `scrollToRealTime` 继续跟随，因此该键的存储值在被用户拖动前不会刷新（这是「不覆盖用户视窗」的代价，已按本轮要求取舍）。
6. **OI 图不写视窗持久化**：OI 是时间窗跟随方（`noopViewportChange`），时间窗由 K 线驱动。
7. **本机后端在沙箱内不可直连**：`curl 127.0.0.1:8787` 超时（`000`），但浏览器可正常取数；因此自动化复测只能在页面侧做，服务进程与下载任务一律未触碰。
8. **构建产物有 >500 kB 分包提示**（Vite 提示，非错误），未做代码分割，属既有状态。
