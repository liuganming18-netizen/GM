1. **问题真实存在且可在实页稳定复现**：修复前，K 线与 OI 两图 `getVisibleRange()` 相等，但 `getVisibleLogicalRange()` 不等，`barSpacing` 不等，**同一 UTC 时间点横坐标最大差 5.4px**（常规切周期）；OI 单位切换后因价格轴宽度变化放大到 **22.4px**；切 1m 后曾出现 **1576px** 的横向错位。旧报告 `docs/验收证据/最终交付报告-LightweightCharts-2026-10-08.md` 关于「切周期对齐已处理」的表述**与实际不符**。

## 3. 根因

官方 Lightweight Charts 的时间轴是**离散索引**（`barSpacing` 均匀，与时间点密度无关）。
两图各自补纯 whitespace 锚点、共用**同一个真实时间点并集网格**，因此同一个逻辑索引在两张图上
指同一时间点。

- **根因①：按真实时间范围同步会把逻辑边界吸附成整数。**
  `getVisibleRange()` 只精确到**整秒**。把它回写成 `setVisibleRange()` 后，目标图的逻辑边界被
  吸附（实测主图 `441.5239` → 跟随图 `441`），`barSpacing` 随之不等
  （实测 `3.937282…` vs `3.930070…`），同一 UTC 时间点横坐标最大差 **5.4px**。
  主图边界本身是分数索引时误差还会更大；OI 单位切换改变价格轴宽度（`paneW 1124→1088`、`psW 84→120`）
  会进一步放大到 **22.4px**。

- **根因②：跟随图数据更新后用自身过期范围覆盖主图。**
  跟随图 `setData()` 会让官方库按**新点集**重算它自己的可见范围。此时把它自己那份范围写回去，
  就会覆盖主图刚同步过来的窗口 —— 切周期/补更早历史后尤其明显（实测 1m 相差 1576px）。

### 4.1 `src/components/LightweightChart.tsx`（新增 3 个辅助函数 + 3 处调用点）

**(a) 新增 `getVisibleLogicalRange` / `applyLogicalRangeTo` / `alignToLeader`（第 634–679 行）**

```ts
function getVisibleLogicalRange(member: ChartSyncMember): LogicalRange | null {
  if (member.disposed) return null;
  const range = safeCall(() => member.chart.timeScale().getVisibleLogicalRange());
  if (!range) return null;
  if (typeof range.from !== 'number' || typeof range.to !== 'number') return null;
  if (!Number.isFinite(range.from) || !Number.isFinite(range.to)) return null;
  if (!(range.to > range.from)) return null;
  return range;
}

function applyLogicalRangeTo(member: ChartSyncMember, range: LogicalRange | null): boolean {
  if (member.disposed || !member.domain || !range) return false;
  try {
    member.chart.timeScale().setVisibleLogicalRange({ from: range.from, to: range.to });
    return true;
  } catch {
    return false;
  }
}

function alignToLeader(hub: ChartSyncHub, member: ChartSyncMember): boolean {
  const leader = hub.members.find(
    (item) => item !== member && !item.disposed && item.role === 'leader',
  );
  if (!leader) return false;
  const range = getVisibleLogicalRange(leader);
  if (!range) return false;
  hub.syncing = true;
  try {
    return applyLogicalRangeTo(member, range);
  } finally {
    hub.syncing = false;
  }
}
```

### 4.2 `src/components/InlineExpandedChart.tsx`（2 处事件捕获 + 1 处文案）

```diff
-          onWheel={markUserViewport}     // K 线宿主容器（第 952 行）
+          onWheelCapture={markUserViewport}
...
-          onWheel={markUserViewport}     // OI 宿主容器（第 1031 行）
+          onWheelCapture={markUserViewport}
```

原因：官方库在容器上挂了**原生** `wheel` 监听器；React 合成事件（`onWheel`）在 React 18+ 走根容器委托，
触发时机晚于原生监听器 → 用户滚轮时「视窗恢复门闸」未被及时解除，恢复逻辑会把用户视窗顶掉。
改为**捕获阶段**（`onWheelCapture`）可保证在原生监听器之前置位 `markUserViewport`。

另更正 1 处与实现不符的 tooltip 文案（第 1030 行，纯文字，无行为变化）：

```diff
- title="…与上方K线共用同一真实 UTC 时间窗（按时间同步，非逻辑索引）…"
+ title="…与上方K线共用同一真实 UTC 时间窗（两图共用同一时间点并集网格，按可见逻辑范围同步，同一时间点横坐标逐点一致）…"
```
