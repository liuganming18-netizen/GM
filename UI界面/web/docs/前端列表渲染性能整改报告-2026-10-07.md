## 二、根因（代码级 + 实测确认）

用户怀疑"一次渲染过多"是**待验证**的；本轮用测量确认它成立，并定位到 6 条叠加因素：

1. **tbody 全量渲染**：`TokenTable` 对 `filteredTokens` 直接 `map`，549 行、每行 10 个 `<td>`、每行一个常驻迷你图 `<svg>`，**同一帧全部挂载**（实测冷启动 `firstRow=953ms` 与 `fullPool=953ms` 完全相同，即首批就是全量）。
2. **全工程零 memo 化**：无 `React.memo` / `useMemo` / `useCallback`，行是内联 JSX，无组件边界。
3. **每轮刷新重建全部对象**：数据层 `mergeMarketRow` 用 `{...prev}` + 新 `oi` 对象，**每 5 s 为全部 549 个 token 生成新对象** → `tokensWithExtras` 重算 → 新数组 → App → TokenTable → 全表重渲。
4. **10 s 新鲜度 tick 再触发一次全表重渲**：`freshnessNowMs` 每 10 s `setState`。
5. **每行现拼长字符串**：每行的 `oiTitle` 悬停说明是约 20 条目的数组 `.filter(Boolean).join('\n')`，含多次 `Date.parse`，每次渲染对 549 行各拼一遍。
6. **549 个 IntersectionObserver**：为上报"可见行"，对全部行注册观察者。

**改前 CPU 采样（12 s，200 µs 间隔，剔除 idle/program）**：`jsxDEV` 938、`ReactElement` 313、`fmtPrice` 229、`TokenTable` 匿名渲染 113、`validateProperty` 113、`runWithFiberInDEV` 106、`updateProperties` 99、GC 88 —— 除 idle/program 外几乎被 React 渲染占满。

**基线证据**（真实改前，代码未改动时采集）：`docs/验收证据/性能基线-列表渲染-改前-2026-10-07.json`（`startedAt 2026-10-07T13:10:04.700Z`）。
另有**复现运行**佐证：`docs/验收证据/性能基线-复现全量渲染-2026-10-07.json`（临时把渲染窗口开到全池以复现"全量渲染"条件，测量后已还原；DOM 22,772 / 549 行 / 1,135 SVG，与真实基线 22,761 / 549 / 1,135 一致）。

## 三、修复方案（按实测选最小有效组合）

### A. 视口内渲染（列表虚拟化）— 主收益
`src/components/TokenTable.tsx`：tbody 只渲染滚动窗口内的行，上下用占位行（`<tr aria-hidden><td style={{height}}>`）补齐总高，保证**滚动条长度与位置和全量渲染一致**。
- 窗口 = 可见行 ± 像素缓冲 `OVERSCAN_PX = 600`（按**像素**换算成行数：行高在窄窗口下会从 ~49px 涨到 ~284px，按行数缓冲会过度渲染）；
- 滚动/尺寸变化经 `requestAnimationFrame` 节流后重算；**区间未变则不触发渲染**；
- 币池、排序、筛选、搜索仍对**全池**生效，只窗口化"渲染"。

### B. 展开行高度与滚动位置
- 行高实测（首行 `offsetHeight`，与常量差 >0.5px 才更新）；
- 展开块高度由 `ResizeObserver` 量测，代入占位换算：`offsetOf(i) = i*rowH + (展开行在 i 之前 ? expandedH : 0)`；滚动位置换算时把展开块高度从 `scrollTop` 中扣除；
- 展开态仍由 `expandedTokenId` 保持：**展开行滚出渲染窗口即卸载重图表，滚回即恢复**（实测见 §五.4）。

### C. 行级 memo + 稳定引用
- 抽出 `React.memo` 的 `TokenRow` 与 `Sparkline`；`oiTitle` 移入行组件，未变化行不再重复拼串；
- `App.handleToggleExpand` 改用 `useCallback`（否则每次渲染换新引用会让全部行的 memo 失效）；
- `InlineExpandedChart` 加 `React.memo`，`onClose` 用 `useCallback` 固定引用。

### D. 数据层身份保持
`src/api/adapters.ts` 的 `mergeMarketRow`：本轮要写入的字段与上一轮**全等时直接返回 `prev`**（判定覆盖全部被写入字段），未变化的行因此跨 5 s 刷新跳过重渲染。

### E. 可见行上报改为直算
去掉 549 个 `IntersectionObserver`，改为按滚动位置直接算出"视口 ± 300px"覆盖的行 id（与原 `rootMargin: '300px 0px'` 等价语义，成本 O(可见行)），集合变化时才回调。
