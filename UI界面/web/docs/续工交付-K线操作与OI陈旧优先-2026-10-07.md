## 二、代码改动（逐个文件）

### 1. `src/components/InlineExpandedChart.tsx` — 滚轮缩放修复（本轮核心缺陷）

**根因**：React 17+ 把 `wheel` 以 `passive: true` 挂在根容器，`onWheel` 里调用
`event.preventDefault()` **无效**（浏览器会报 "Unable to preventDefault inside passive
event listener"）。因此缩放生效的同时**整页会跟着滚动**，且缩放行为不可靠。

**修复**：改为在 `useEffect` 里用原生
`addEventListener('wheel', listener, { passive: false })` 绑定到 K 线画布与 OI 画布；
处理函数经 `wheelHandlerRef` 每次渲染刷新，避免重复绑定/解绑。
处理逻辑本身（以鼠标所在时间为锚点的缩放、Shift/横向滚动平移、视窗夹在已加载 K 线域内）
保持不变。

证据：探针在 `document` 冒泡阶段读到 `cancelable: true, defaultPrevented: true`，
且页面 `window.scrollY` 与最近可滚动祖先 `scrollTop` 全程为 0。

### 2. `src/components/TokenTable.tsx` — 陈旧 OI 快照优先选择修正

**根因**：旧判定 `publicOiPair` 只检查「数量与名义额都有值 + 同一行时点相等」，
**不看年龄**。实测 `binance:0GUSDT`：

- `/markets` 行 `oi_time = 12:39:10Z`（较新，采集器轮询）
- public-extras 快照 `amount / usd @ 12:05:00Z`（较旧，5m 边界采样，快照 age > 900s 阈值）

旧逻辑让**较旧的快照数量覆盖较新的列表数量**，属陈旧优先。

**修复（现规则）**：

- **数量**取「较新的一侧」：快照必须成对（同一 `openInterestHist` 行）**且**其指标时点
  **不早于**列表行 OI 时点，才允许作为数量来源；否则用列表值。
- **名义额**列表行通常没有（币安 526 行 `open_interest_usd` 全为 null），只能来自快照；
  它**单独**标注自身指标时点与陈旧状态，不与数量拼接、不换算、不倒填。
- 悬浮说明显式写出「陈旧优先已阻止」与「数量/名义额不同源不同时」的提示。

实页结果（0GUSDT）：`数量: 3680.06万 单位待核验 时效内`（12:39:10Z，列表）＋
`名义额: 1099.18万 USD 陈旧`（12:05:00Z，快照独立时点）。
