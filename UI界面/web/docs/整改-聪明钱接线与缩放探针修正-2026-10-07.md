## 1. 关键更正：币安**公开无鉴权**聪明钱接口真实存在

先前报告写「币安公开 API 结构上没有这些字段（无金额 / 无均价 / 无身份）」——
该判断**只对 `/fapi/v1/futures/data/*` 那几个聚合比率端点成立**。币安另有独立入口：

```
GET https://www.binance.bh/bapi/futures/v1/public/future/smart-money/signal/overview?symbol={S}&timeRange=ALL
GET https://www.binance.bh/bapi/futures/v1/public/future/smart-money/signal/details/stats?symbol={S}&timeRange=ALL
GET https://www.binance.bh/bapi/futures/v1/public/future/smart-money/signal/details/list?symbol={S}&timeRange=ALL&page=1&rows=10&sortingField=TIME&sortingOrder=DESC
```

与用户 Chrome 已打开的 `https://www.binance.bh/zh-CN/smart-money/signal/ARXUSDT` 是同一组数据（页面自述每 60 秒更新）。

**实测事实（`docs/验收证据/币安聪明钱真实响应_2026-10-07.json`，checkedAt `2026-10-07T15:40:22Z`）**

| 事实 | 结果 |
|---|---|
| 鉴权 | **不需要**。仅 `Accept: application/json`，无 cookie、无 Authorization ⇒ **HTTP 200** |
| `timeRange` | **必填**。`details/stats`、`details/list` 缺该参数 ⇒ **HTTP 400** `{"code":"000002","message":"illegal parameter"}` |
| `overview` 的 `timeRange` | 可选但**必须显式传 `ALL`**：缺省时口径不同（同刻 `longTraders` 172 vs 168），会与 `stats` 不自洽 |
| 无效/缺失 symbol | **HTTP 200 + `data:null`**（不是 4xx，客户端须按 `data==null` 判空） |
| `page`/`rows`/`sorting*` | 可选（有默认值），缺失仍 200 |
| 覆盖抽样 | 从本机 526 个币安合约等距抽 **30 个，30/30 返回真实数据** |

**六槽取值（全部真实字段，无任何推算）**

| 槽位 | 来源字段 |
|---|---|
| 持仓额（USDT） | `stats.longPositions` / `stats.shortPositions`（**已是 USDT 金额**，不是数量） |
| 巨鲸占比（%） | `stats.longWhalePositions ÷ stats.longPositions`（同一响应内分子分母） |
| 均价 | `overview.longTradersAvgEntryPrice` / `shortTradersAvgEntryPrice` |

来源另提供（已进悬浮说明，未新增列）：交易员人数 `longTraders/shortTraders`、
巨鲸人数 `longWhales/shortWhales`、巨鲸均价 `longWhalesAvgEntryPrice/shortWhalesAvgEntryPrice`、
总持仓 `totalPositions`、交易者总数 `totalTraders`、名义多空比 `longShortRatio`、数据时点 `updateTime`。

`details/list` 另按 `userType`（0/2）× `side`（BUY/SELL）给出 `traders / currentPositions / currentQty / avgEntryPrice`，
即页面上「交易员人数 / 当前仓位 USDT / 平均开仓价」三列的逐行来源。

## 3. 实测缺陷与修复：每 5 秒刷新会抹掉刚取到的聪明钱真值

**现象**：接线后展开行仍恒显示 `巨鲸占多/空持仓比: — / —`、`多空均价: 暂无数据 / 暂无数据`。

**根因**：列表每 5s 刷新走 `/api/v1/markets`，该接口当前**不含**聪明钱原始字段 ⇒
`adaptMarket` 给出空态；而展开行是按需从币安接口取到的**真值**。
`mergeMarketRow` 原先无条件 `smartMoneyLong: next.smartMoneyLong` ⇒ **每 5 秒把真值抹成空**。

**修复**：只在列表**确实带了值**（`hasSmartMoneyData`）时才替换，否则沿用上一轮；
同时保留身份保持语义（引用相等或逐字段等值都算未变化，避免破坏性能整改的跳过重渲染）。

**可复核的前后对比**（`docs/验收证据/回归-merge聪明钱-修复前复现_2026-10-07.log` vs `-修复后_2026-10-07.log`，
同一测试 `test_merge_smartmoney_2026-10-07.ts`，后者跑在把 `mergeMarketRow` 还原为旧写法的临时副本上）：

### 4.3 缩放探针修正说明（回应验收第 ⑥ 条）

旧 `readView()` 用 `/视窗[^\n]*?([\d.]+)\s*[~-]\s*([\d.]+)/` 取「视窗后第一对数字」，
非贪婪匹配把日期里的 `2026-10` 当成一对数字 ⇒ `span = 10 − 2026 = −2016`，
且三次读数得到的是**同一条错误截断串**，于是 `zoomReversible` / `panKeptSpan` 被这个恒定错误值判成 `true` —— **假通过**。

本轮修正三处：

1. **解析**：只接受严格 ISO 时间戳（`YYYY-MM-DDTHH:MM:SS(.sss)Z`），并要求 `endMs > startMs`；
   解析失败一律返回 `null`，相应判定随之返回 `null`（不再返回 `true`）。新增 `parseOk` 作为证据有效性闸门。
2. **平移测法**：视窗被夹在「当前已加载 K 线域」内，**在全域状态下拖动本就被夹住不动**。
   旧版在 zoom-out 之后拖动 ⇒ 等于在全域测平移。现在**先放大再拖**，
   并新增 `panMovedWindow` / `panShiftedMs` 证明窗口真的位移了（而不只是跨度没变）。
3. **币池计数**：旧正则 `/筛选后 (\d+)\/(\d+)/` 与页面实际文案「共 N 个标的」不匹配，恒返回 `null`；
   已按实际文案修正。

旧 JSON `余项验收-虚拟列表与K线_2026-10-07.json` 中 `view.raw="视窗 2026-10"`、`span=-2016`、
`zoomInChangedSpan=false` 属**错误解析**，**不得再作为缩放证据引用**；以本轮
`余项验收-虚拟列表与K线-修正后_2026-10-07.json` 为准。

## 9. 追加核查（2026-10-07T15:55–16:00Z）：`updateTime` **不是**新鲜度字段

本轮做了一件上一轮没做的事：**验证来源自带的时点字段到底推不推进**。结果推翻了我自己写进悬浮说明的一句表述。

`overview` + `details/stats`，ARXUSDT，`timeRange=ALL`。证据：`docs/验收证据/聪明钱新鲜度-updateTime推进核查_2026-10-07.log`

### 9.2 结论

- `overview.updateTime` **不承载「数据是否新鲜」语义**——业务字段在 73 秒内全部变化，它一动不动。
- **真实新鲜度字段是 `details/list[].lastTradeTime`**：同刻实测 `1791388494477` = `2026-10-07T15:54:54.477Z`，age **≈ 59s**，与页面自述「每 60 秒更新」吻合。
- 因此**任何**用 `updateTime` 判断/展示陈旧度的实现都是错的（会把 1 分钟前的活数据标成 9.6 小时前）。
- 顺带补齐 `details/list` 边界：`timeRange` 必填（缺 ⇒ **400** `{"code":"000002","message":"illegal parameter"}`）；无效 symbol ⇒ **200** + `data:[]`、`total:0`；`userType` 实测有 `2`（traders 180/88，与 overview 同量级）与 `0`（各 1 人、仓位 314.78 / 21.34，`lastTradeTime` 已陈旧至 2026-07 / 2026-09）。
