### 1. 执行视图周期选择

- 选项：日线 / 12h / 8h / 4h / 1h / 30m / 15m / **5分线（禁用）**，与全站 `Timeframe` 同一套值，不做第二套命名。
- **事实边界**：`GET /backtests/{id}/chart` 只返回**执行周期（15m）的真实 K 线**。
  比执行周期**更粗**的周期由这些真实 15m K 线按 **UTC 边界精确聚合**得到：

  ```
  O = 桶内首根 open      H = 桶内 max(high)     L = 桶内 min(low)
  C = 桶内末根 close     V = Σ volume          t = 桶起点
  ```

  这是这些周期的**定义式**算法（不是均值、不是插值、不改时间戳），成交量精确可加。
- 比执行周期**更细**的 5m **无法**从 15m 还原 ⇒ 按钮禁用并在 `title` 写明原因（不插值、不合成）。
- 换 run 时周期自动回到该 run 自己的执行周期，不沿用上一条的视角。

**实测聚合自洽性**（ACEUSDT / BNBUSDT / XVSUSDT 三条 run 一致）：

| 目标周期 | 实测根数 | 校验 |
|---|---|---|
| 15m（执行周期） | 17376 | 原始 |
| 1h | 4344 | 17376 ÷ 4 ✅ |
| 4h | 1086 | 17376 ÷ 16 ✅ |
| 日线 | 181 | 17376 ÷ 96 ✅；窗口 2024-01-01 → 06-29 共 181 天 ✅ |

### 3. 逐笔明细 → 水下回撤联动

点「⑤ 逐笔明细」任意一行 ⇒ ③ 资金分析自动：

1. 切到 **「水下回撤」** 视图；
2. 时间轴定位到该笔的 `[entry − 1h, exit + 1h]`，并夹到本 run 权益序列真实范围内（不越界、不外推）；
3. 表头出现 `已定位 <trade_id> ✕` 徽章，点击即恢复全区间；
4. 读数条补一行 **「该笔区间」**（精确到分钟）——面板窄、时间轴有物理缩放上限，精确区间由此给出，不依赖图形缩放精度。

**定位优先用索引区间**（`setVisibleLogicalRange`）而不是时间区间：面板约 590px 宽、时间轴有最小 bar 间距，「时间 → 逻辑坐标」换算会把区间放大一截；直接落在真实权益点上更准。

同时把 ③ 的视图切换按钮本色由绿色 `bg-emerald-600` 改为 `--ds-accent` 品牌蓝（设计规范：绿色只用于涨跌，选中态用蓝）。

### A. 连带缺陷：执行视图 K 线恒为 0 根（已修）

- **现象**：④ 执行视图一直显示 `0 根` + 「无真实 K 线数据」，K 线图整块空白。
- **根因**：落盘 `chart.json` 的 `candles` 是**长度 6 的数组元组**：

  ```json
  [1704067200000, 11.665, 11.719, 11.652, 11.709, 12762.9]   // [t,o,h,l,c,v]
  ```

  而前端 `labCandlesToBars` 按对象 `{t,o,h,l,c,v}` 读 ⇒ 全部字段 `undefined` ⇒ 被过滤光。
  （后端源码 `backtest_runner.py` / `backtest_api.py` 写的是**对象**，与落盘格式不一致。）
- **修复**：前端 `normalizeCandle()` 两种格式都接受，统一归一化 ⇒ 落盘端往哪边收敛都不会再画不出图。
- **附带**：图载荷 `chart.trades[].trade_id` 实测为 `null`（`GET /trades` 给的是真实 `trd_N`）⇒ 选中高亮 / 图上点击定位全失效。前端用**两边都有的真实时间戳**把 id 换回来（`tradeIndex` 入参），不猜、不造 id。

### B. 连带缺陷：净值图默认只显示最后 10 天（已修）

- **现象**：「净值对比」默认视图只显示 `06-19 → 06-29`，标着全区间却看不到整段。
- **根因**：lightweight-charts `timeScale.minBarSpacing` 默认 0.5px ⇒ 17376 个 15m 净值点在这块约 510px 宽的面板里最多只能放下约 1020 个 ⇒ `fitContent()` 被夹住。
- **修复**：这是**线图**（不是 K 线柱），亚像素密度没问题 ⇒ `minBarSpacing: 0.01`。
- **实测**：默认视窗从 `06-19 09:00 → 06-29 23:45` 变为 **`01-01 00:00 → 06-29 23:45`**（完整窗口）。

## 三、遗留（未做，需另立任务）

1. **`/metrics.max_drawdown_pct` 恒为 `0.0`**（后端缺陷）。
   实测 ACEUSDT：后台 `max_drawdown_pct = 0.0`，而按同一权益序列 + `initial_equity` 展开的真实峰值回撤 = **0.6574%**。
   影响：⑥ 列表「回撤」列全是 `-0.0000%`；③ 因此常驻 `回撤 ✗ 不一致` 异常徽章（这个徽章是对的，是后台值不对）。
   **属后端 `backtest_runner.py` 口径问题，该文件当前由并行窗口在改，本窗口不动。**
2. **落盘 `candles` 为数组元组 vs 源码写对象** —— 前端已兼容，但后端两侧仍不一致，建议收敛。
3. **`chart.trades[].trade_id = null`** —— 前端已兜底，后端应补真实 id。
4. ⑥ 运行表在前 50 条内**有成交的 run 不稳定**（同批 run `created_at` 相同 ⇒ 排序不稳定 + 并行窗口持续新建）⇒ 验收脚本须动态挑选，不能写死 run_id。
5. **④ 与 ③ 的默认视窗尺度不一致**（已知边界，非缺陷）：③ 是线图，`minBarSpacing: 0.01` 后可铺满整段（`01-01 → 06-29`）；
   ④ 是 K 线柱，17376 根 15m 蜡烛在约 590px 宽内每根只有 0.034px，柱体无法分辨 ⇒ 默认只显示最近约 15 天。
   两侧在**点中某一笔后会自动对齐到同一区间**（这正是本次联动做的事），故交互上不影响判读；
   若要让默认也对齐，需另定设计（例如默认周期改粗），本轮未做。
